
Start of lesson:
- Have learners create a new 2D project called 'A Game About Blobs'
- Go to Project Settings > Player > Active Input Handling and set it to 'Both' 

Do the slides up until and including the "Let's make a State Machine" slide.

Create a prefab, 'Blob'
- Add a dynamic sprite child object
- Set the Sprite Renderer to 'Draw Mode' - Sliced
- Create a 'Blob' tag and apply it on both objects

Write the 'BlobSize' script. Add 'OnValidate()' and show it working in editor.

Write the BlobCollision script. Add it to the dynamic sprite.

Add two Blob prefabs to the scene
- make one larger than the other through the BlobSize component (or use the randomise toggle)

Demostrate the BlobCollision script working by manually moving the blobs into each other.
(Colour will make it easier to see which Blob is "eaten")

Challenge:
- Write a simple script to control a blob with player inputs
- Give them 5 minutes - remind them we have no walls so no need for physics

Attach the player script to one of the blobs and demonstrate it working.

Design the state machine in Draw.IO, as a flowchart
- Walk and Idle go back and forth
- Either can lead to Hunt or Flee
- Hunt and Flee lead back to Idle
- Label with reasons for state changes (idle timer, proximity and player size, etc)

Write the BlobAI script and attach it to the blob's body.

Demonstrate the AI blob reacting to the player depending on the sizes.

///// Part 2
Discuss how we made one basic state machine - it will only work with the Blob.
- Discuss how we need a solid foundation for our States, reusable behaviour
- But each state needs to work differently
- Inheritance is perfect for this, but we don't want the base 'State' to be used
    (like our HasTarget and Interaction scripts from last week)

Go back to the slides and finish them off (2 slides)
- We'll use the abstract accessor to create a skeleton StateBehaviour script
- Then we can Inherit and build out each state separately

Create the StateBehaviour and StateMachine scripts. Create the Idle and Walk scripts.

In the scene:
- Disable the old BlobAI blob
- Add a new blob prefab and attach to its body
    - StateMachine
    - IdleState
    - WalkState

Demonstrate those working (back and forth between idle and walk).

///// Part 3
Our previous AI was designed to only interact with the player.
- What if we want them to all respond to each other?
- We're going to upgrade our blobs to be aware of their surroundings
- They'll make a choice based on what they find.

Write the BlobAwareness script together
- point out it is similar to the TargetList script from the auto-turret

Create a new variant of the original Blob prefab
- Call this one 'BlobStateMachine'.
- Add a child object to the Body, with a CircleCollider2D as a trigger
- attach the BlobAwareness script to the trigger

Add a bunch of SmartBlobs to the scene, randomise their size, and hit play.
Demonstrate how they choose different actions depending on their current situation.

///// Part 4
For the remainder of Week 9's lesson, have the learners do Assessment 1 Part 1 in small groups.
